# Table sources & provenance

The three conversion tables are generated by `../build_tables.py` from the **OpenCC**
dictionary data (Open Chinese Convert), the de-facto-standard, well-tested SC↔TC
dataset. OpenCC dictionary data is licensed **Apache-2.0**.

* Upstream: <https://github.com/BYVoid/OpenCC> — `data/dictionary/`
* Raw files pulled (from `master`):
  * `STCharacters.txt` → **`01_characters.csv`** (single-character SC→TC, one-to-many kept)
  * `STPhrases.txt`    → **`02_vocab_general.csv`** (phrase-level SC→TC disambiguation)
  * `TWPhrases.txt`    → **`03_vocab_regional.csv`** (Taiwan-divergent vocabulary)
  * `TSCharacters.txt` → used only to reverse Taiwan keys back to the simplified forms
    used in `/text`, so table 3 can be scoped to terms that actually occur in the book.

`03_vocab_regional.csv` is additionally **filtered to terms present in `/text`** and sorted
by frequency, and its `chosen` column is intentionally left blank for the author.

## Refresh

```sh
python3 "../build_tables.py"            # re-download from OpenCC and rebuild all three CSVs
```

This overwrites `01`/`02` wholesale. For `03`, the author's hand-made **`chosen` decisions
are preserved** (carried over by `sc` key); only brand-new terms arrive with a blank `chosen`.
`build_tables.py` re-downloads from OpenCC on each run; pass `--offline` to rebuild from the
local `_raw_*.txt` cache instead. That cache is gitignored — there is no committed copy of the
raw OpenCC files. The day-to-day conversion (`../convert.py`) reads only these CSVs, no network.
